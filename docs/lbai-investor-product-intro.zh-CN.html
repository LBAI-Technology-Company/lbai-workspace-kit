Product Overview

企业不是缺少 AI 模型，而是缺少让 AI 稳定进入正式工作的操作系统。

通用模型可以回答问题，但企业真正需要的是把任务、证据、权限、审计、复盘和知识沉淀连接起来。 LBAI 的切入点不是替代员工，而是把员工每天与 AI 协作产生的工作过程，变成组织可复用的数据资产。

Problem

AI 办公落地的三个断点

这些断点决定了企业 AI 能不能从个人效率工具，变成可规模化的组织能力。

01

聊天不可追踪

任务目标、缺失信息、执行过程和最终输出散落在对话里，无法成为可交接的正式工作记录。

02

资料无法沉淀

会议纪要、客户反馈、项目材料和制度文件缺少统一入口，历史背景难以回到新任务中。

03

交付缺少边界

没有来源、敏感信息、review 边界和证据要求，AI 输出很难稳定进入正式业务流程。

Employee Flow

员工从安装到日常工作的完整流程

员工不需要理解复杂后端，只需要用同一套 `/lbai-*` 命令把资料、任务和交付纳入标准流程。

Step 1 安装 CLI 通过 Mac / Windows 安装脚本获得 `lbai` 命令。
Step 2 登录认证 配置 GitHub Token，可选配置后端知识服务 API Key。
Step 3 初始化工作区 绑定员工 private GitHub repo，写入标准 workspace 模板。
Step 4 打开 AI 工具 用 Cursor 或 Codex 打开工作区，运行 `/lbai-init`。
Step 5 沉淀资料与任务 用 `/lbai-add-evidence` 和任务三步链路处理日常工作。
Step 6 检索与交付 调用后端 evidence search，收尾检查后同步到 GitHub。

  • 补充来源、时间、摘要、敏感边界和是否需要负责人 review。
  • 资料进入 Git 管理后，可被后端同步、解析和检索。

功能细节

  • 执行阶段要求先找资料、列计划，再产出可落盘的任务结果。
  • 收尾阶段检查来源、review、阻塞项和交付文件，避免只停留在聊天里。

  • 后端返回结构化 `evidence_pack`，包含来源、摘要、相关性和限制说明。
  • 任务执行时优先引用检索证据，降低 AI 编造事实的风险。
 让历史证据进入新任务，形成跨员工知识复用。 契约已落地

  • 让当前 AI 执行资料归档、任务创建、任务执行、收尾检查等链路。
  • 按场景评估结果打分，产出 human review 和可追溯的实验记录。

Architecture

从个人工作区到公司知识层

员工端轻量落盘，后端集中处理。这个边界让产品能先进入真实工作流，再逐步扩展为组织知识基础设施。

资料沉淀 员工把原始资料保存为标准 evidence，不在聊天中流失。
事实抽取 后端将资料转为 `fact_event`，保留来源和时间脉络。
证据检索 任务发起时返回 `evidence_pack`，而不是让 AI 凭空回答。
结果回流 任务输出和收尾记录继续进入 workspace，形成复利。
效果迭代 Prompt Lab 用模拟任务评估 AI 表现，把问题转成可 review 的 prompt 改进。

Execution Path

落地路径与扩展空间

先把员工端工作流跑通，再用后端 service 承接跨员工知识沉淀和检索，最后扩展到企业级治理。

Phase 1

员工端标准化

  • CLI 安装与 workspace 初始化
  • Cursor / Codex `/lbai-*` 工作流
  • Evidence、Tasks、Ledgers 落盘
  • `/lbai-self-iterate` Prompt Lab 实验
  • GitHub commit / push 同步
Phase 2

知识 Service MVP

  • GitHub webhook / 定时同步
  • 文档解析与事实抽取
  • Schema 校验与 `fact_event` 入库
  • `POST /v1/search/evidence` 检索
Phase 3

企业级知识治理

  • 权限过滤和审计日志
  • 冲突检测和字段治理
  • 管理后台和同步状态监控
  • 跨团队知识复用、质量评估与 AI 效果优化

从“每个人都在用 AI”，升级到“公司正在积累 AI 可用的组织记忆”。

这就是 LBAI Workspace Kit + Service 的长期价值。

Product Summary

这个产品展示的三件事

  • 入口足够轻：员工仍然在 Cursor / Codex 里工作，不需要迁移到新系统。
  • 数据足够深：任务、证据、岗位记忆、交付记录和自迭代实验持续沉淀。
  • 扩展足够清晰：从员工端 kit 到后端 service，再到企业知识治理平台。
